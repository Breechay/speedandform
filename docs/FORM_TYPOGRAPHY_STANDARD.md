# FORM typography standard

Owner: Brice. Added September 14, 2026. Applies to app and site. This is a standing acceptance rule for all future surface work, not a request to change every screen at once.

## Make the information easy to read

- Establish one clear focal heading, then supporting text, then quiet labels. Do not let every card compete at display size.
- Set body text for comfortable reading before styling labels. Web instructional body usually starts at 16–18px with 1.5–1.7 line height; native uses semantic text styles and Dynamic Type. These are starting ranges, not permission to ignore actual rendering.
- Keep paragraphs around 45–65 characters per line. Collapse columns when they squeeze text, not only at a familiar device breakpoint. No clipped headings, forced tiny text or body copy with tight display tracking.
- Put distances, loads, paces and units in clear groups. Use aligned definition lists or tables for comparisons. Use tabular lining figures for comparable numeric columns and changing values; decorative oldstyle figures must not reduce legibility.
- Labels identify content, not decorate it. Prefer short labels with restrained tracking. Do not render instructions in tiny uppercase text. Preserve readable contrast for secondary text.
- Use a consistent spacing scale. Give each label its content, each paragraph its breathing room, and each section a clear boundary. One divider per boundary, never stacked rules or an input underline plus decorative separator.
- Make entire disclosure headings comfortable touch targets. Let titles and subtitles wrap naturally. Long units and division names must not collide with values or disclosure controls.
- Preserve each surface's established font and color system. The shared standard governs hierarchy and readability; it does not make all app and site surfaces identical.
- Plain wording: name the object, state the action, explain what to notice. Use practice, practiced and practicing. Prefer periods, commas, colons or a rewritten sentence over em dashes.

## Review before calling it finished

Inspect desktop, tablet portrait/landscape and phone layouts. Web targets include 375/390/430, 768/1024 and 1440px plus 200% text/zoom. Native includes larger Dynamic Type. Check longest labels, real data, missing data, open disclosures, keyboard focus, forms and footer. Verify normal-text contrast of at least 4.5:1 and 3:1 for large text. Respect reduced motion. Keep usable content when animations are disabled.

Do not hide overflow to conceal a layout defect or shrink everything to fit. Use spacing and stacking first. Print requires its own rendered check if claimed as a deliverable.

Record exactly what was inspected. Source review is not a device test. A numerical design score is not acceptance evidence. If a device or capability is unavailable, leave that check open.

This newer standard takes precedence where older styling instructions require unreadably small labels, excessively tracked text or decorative numerals for data comparisons.

## September 17 owner corrections

The FORM wordmark ends with a **round period**, never a font-dependent square. Position it on the lettering baseline, not as a raised middle dot; verify the rendered mark with enlarged text and fallback fonts. Preserve its readable identity text. The website header/footer and José preview were corrected in [PR134's release](audits/APP-PREVIEW-POLISH-20260917.md); this is not a claim that every unrelated or native surface was edited.

Breechay Sculpt's large illustrative phase numerals use its **sans-serif** family. Do not reintroduce a decorative serif 01 or the removed “Sculpt · The Frame” label beneath Adrian. Keep each surface's distinct material and typography rather than making FORM and Sculpt identical.
