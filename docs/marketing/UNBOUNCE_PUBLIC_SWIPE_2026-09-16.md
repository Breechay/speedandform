# 1. Race Pace Durability — active

Current page already follows most of the useful conversion pattern:

1. one campaign-specific question: `Can you keep the pace?`
2. literal product facts immediately visible;
3. low-friction free preview before purchase;
4. real-athlete visual continuity from Meta;
5. proof near the offer;
6. explicit fit / not-yet qualification;
7. one price and one product;
8. checkout separated from coaching;
9. post-purchase page has a real operational job: verify and unlock.

### Highest-value tests after first traffic

Do not silently add these before we have behavior data:

- **CTA language:** `Try Weeks 1–4 free` vs `See the first four weeks`.
- **Proof placement:** move one verified FORM result closer to the first CTA vs current Hope/José live-study placement.
- **Length:** current full argument vs a shorter campaign-only page.
- **Sticky mobile CTA:** only after we observe meaningful mobile scroll depth / CTA misses.
- **Objection FAQ:** add only objections repeated by actual visitors/buyers.

### Reject

- timer/countdown urgency;
- fake scarcity;
- forced email gate before the free preview;
- a generic testimonial carousel disconnected from the plan;
- hiding the $79 price;
- introducing app signup before the visitor understands the plan.

# 2. FORM app — parked concept

The landing page should sell the **daily job**, not the architecture.

### Working story

**Hero:**
`Know what to run today.`

Supporting idea:
FORM turns a running plan into the thing you need now: today's session, the pace, the reason, then a simple way to file what happened.

### Page sequence to explore

1. one phone/product screenshot with Today visible;
2. `Know what to run today.` + trial CTA;
3. three jobs, not feature names:
   - see today's run;
   - know the pace / effort;
   - file what happened;
4. one short real workflow: Today → run → file → next;
5. proof from actual athletes / sessions;
6. what FORM is and is not;
7. trial / paid pricing when final;
8. App Store CTA.

### Conversion principle borrowed from product/signup pages

Show the product doing the core task before asking someone to understand the larger system. Keep account creation/trial friction as late and light as product constraints allow.

### Do not claim yet

- adaptive AI coaching unless shipped and verified;
- automatic personalization beyond actual product behavior;
- Android availability if absent;
- outcomes the app itself cannot substantiate.

# 3. Forge — parked concept

Forge should be shown as an **execution product**, not as bodybuilding theory.

### Working story

Potential simple territory:
`Open the workout. Do the work.`

or, depending on final positioning:
`Build your frame.`

The first screen should make it obvious what the user gets today rather than explain phases/program logic.

### Page sequence to explore

1. strong body/result visual or app screenshot;
2. plain outcome + product role;
3. actual workout surface;
4. `What you do today` → exercises, sets, reps, progression;
5. program structure only after execution is clear;
6. adherence/progress proof;
7. trial / purchase CTA when commercial model is locked.

### Useful product-page pattern

Demonstrate the real object. A workout card / Today screen carries more credibility than a long list of abstract features.

### Reject

- transformation guarantees;
- generic `science-backed` claim without precise support;
- fake before/after imagery;
- overloading the hero with program phases or exercise science.

# 4. Coaching homepage challenger — parked concept

This is a lead-capture surface, so the page should lower uncertainty and make the next step obvious.

### Working hero territory

`Get better at running.`

`Running coaching in Miami.`

`Tell me what you're training for.`

The control has already shown that plain local coaching language can produce a real inquiry. Do not replace that evidence with a more intellectual positioning exercise.

### Challenger sequence

1. plain coaching promise + location;
2. real FORM athlete image / practice environment;
3. verified Simon result;
4. what 8 weeks includes;
5. Run Development $1,200 / Run + Strength $1,800;
6. who it is for in plain language;
7. first track assessment complimentary;
8. short intake.

### Lead-capture principle

Ask only for information Brice will actually use to decide the first coaching move. Every field should earn its place. The intake can become more detailed after the visitor has enough motivation to complete it, but the page should never feel like an application for permission to run.

### Thank-you surface

After inquiry, the confirmation should tell the person exactly what happens next:
- Brice reads it;
- reply comes from `brice@speedandform.com`;
- expected response window;
- optional useful next action, not another sales pitch.

---

# Shared rule across all four surfaces

**One page = one visitor state + one next action.**

Do not make one page simultaneously explain the philosophy, sell coaching, sell an app, sell a plan, and recruit community participation. Cross-links can exist lower down, but the first conversion path must stay singular.

The visual system can remain FORM-level and distinctive. The copy should not require FORM-level knowledge.
